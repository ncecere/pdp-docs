title: Running Pi Durable Platform
description: "What a Pi Durable Platform install is made of, what you need before you start, the ports, and how to install it."
---

Pi Durable Platform is one Go binary with the web app embedded, plus an agent runtime image. You run the platform; the platform starts a runtime for each agent while it's used.

## What an install is made of

| Part | What | Port |
|---|---|---|
| **The platform** (`ghcr.io/ncecere/pi-durable-platform:v0.1.2`) | Web app, API, OAuth endpoints, background loops (hibernation, clean-up, thread events) | `8098` (`LISTEN_ADDR`): put your HTTPS ingress in front |
| **The agent gateway** (the same process) | The model proxy, the MCP proxy, and usage and thread reports, for agents only | `8099` (`AGENTS_GATEWAY_ADDR`): never expose it outside the cluster |
| **The metrics port** (the same process; optional) | `GET /metrics` for Prometheus, and nothing else, with no authentication | Off unless `METRICS_ADDR` is set; the chart sets `:9090`. Never expose it: see [Metrics and tracing](/docs/operate/metrics-and-tracing) |
| **Agent runtimes** (`ghcr.io/ncecere/pi-durable-platform-runtime:v0.1.2`) | One Node.js process with Pi's durable package per running agent; started by the platform | `4100`, reached by the platform only |
| **PostgreSQL**, platform database (`DATABASE_URL`) | People, teams, templates, agents' records, keys, audit log, usage | |
| **PostgreSQL**, agents database (`AGENTS_DATABASE_URL`) | One schema and role per agent: its conversations | |

Both images are multi-arch (linux/amd64 and linux/arm64), run as non-root users with read-only root filesystems, and are signed with cosign keyless signing. Pin them by digest; the digests are on the [v0.1.2 release page](https://github.com/ncecere/pi-durable-platform/releases/tag/v0.1.2).

## Requirements

- **Kubernetes**, for the agent runtimes: 1.27 or newer for the Helm chart, with a network plugin that enforces NetworkPolicy. The `kubernetes` launcher needs nothing else; the `agent-sandbox` launcher needs [Kubernetes Agent Sandbox](https://agent-sandbox.sigs.k8s.io) installed.
- **PostgreSQL 17** (the version the platform is developed and tested with), with two databases. They can be on one server. See [Databases](/docs/operate/databases).
- **An OIDC identity provider** for sign-in. See [OIDC sign-in](/docs/operate/oidc).
- **HTTPS**: `APP_URL` must be `https` unless it's a loopback address.
- **Models**: at least one provider your agents can use, or an OpenAI-compatible server as the default model. Without one, agents run on the scripted `demo` model.

## Launchers

`AGENTS_LAUNCHER` chooses how a runtime starts:

| Launcher | A running agent is | Hibernating | Waking | For |
|---|---|---|---|---|
| `local` | a child process of the platform | stops the process | starts it | development only; refused unless `APP_URL` is loopback |
| `kubernetes` | a pod `agent-<id>`, its secrets in a Secret of the same name | deletes the pod | creates it | production ([Install on Kubernetes](/docs/operate/kubernetes)) |
| `agent-sandbox` | a Sandbox `agent-<id>` around the same pod | suspends it | resumes it | production with Agent Sandbox ([Agent Sandbox](/docs/operate/agent-sandbox)) |
| `agent-sandbox` with a warm pool | a standby runtime claimed from a `SandboxWarmPool` | releases the claim | claims and activates one | faster wakes ([Agent Sandbox](/docs/operate/agent-sandbox#warm-pool)) |

## Install paths

| Path | Use it when |
|---|---|
| [Helm chart](/docs/operate/kubernetes) (`oci://ghcr.io/ncecere/charts/pi-durable-platform`, signed) | You want values instead of patches. It deploys the platform, the agents namespace, the platform's Role and the NetworkPolicies that isolate agents |
| [Kustomize](/docs/operate/kustomize): a base, overlays for each launcher, components and examples | Your cluster is managed with Kustomize, or with Flux or Argo CD on plain manifests. It is generated from the chart |
| [The objects by hand](/docs/operate/manual-manifests) | You want to understand what the chart creates, or build your own |
| [Try it locally](/docs/get-started/try-it-locally) | You want to try it on your own machine |

Both the chart and the base need a cluster whose network plugin enforces NetworkPolicy, PostgreSQL 17, and an OIDC client. They don't install PostgreSQL, the ingress controller or Agent Sandbox. The repository's `compose.yaml` only starts a development PostgreSQL; there is no production Compose file.

## Commands

```text
pi-durable-platform serve                 the API, the web app and background loops (the image's default)
pi-durable-platform migrate               apply database migrations and exit
pi-durable-platform doctor                check the configuration, PostgreSQL, migrations, the keys and the agents database
pi-durable-platform prune-agent-storage   remove agent storage no agent owns (--dry-run)
pi-durable-platform prune-roles           drop agent database roles no agent owns (--dry-run)
pi-durable-platform rekey                 re-seal every stored secret under the current ENCRYPTION_KEY (--dry-run, --batch)
pi-durable-platform version               print the version
```

The platform runs as one replica, or as several behind one Service: two is the supported setup for staying up through node drains and rollouts. See [Running several replicas](/docs/operate/replicas) and [Install on Kubernetes](/docs/operate/kubernetes). To see what it is doing, see [Metrics and tracing](/docs/operate/metrics-and-tracing).

Configuration is environment variables, optionally over a YAML file: see [Configuration](/docs/operate/configuration).
