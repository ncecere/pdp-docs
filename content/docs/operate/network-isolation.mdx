Pi Durable Platform is built so that agents need almost no network: in proxy mode they reach models and MCP servers only through the platform. Enforce that with NetworkPolicies. The [Helm chart](/docs/operate/kubernetes#network-policies) and the [Kustomize](/docs/operate/kustomize) base ship them; this page lists the connections they allow, and the policies written by hand.

## The connections

| From | To | Port | Why |
|---|---|---|---|
| Your ingress | Platform | 8098 | Web app, API, OAuth, and webhook deliveries (`/v1/hooks/…`) from the systems that start [triggered runs](/docs/teams/triggers) |
| Platform | Agent runtimes | 4100 | Relaying conversations, activation (warm pool) |
| Agent runtimes | Platform gateway | 8099 | Models and MCP servers in proxy mode, thread and usage reports |
| Platform, agent runtimes | PostgreSQL | 5432 | The platform: both databases. Runtimes: the agents database only |
| Platform | Kubernetes API | 443/6443 | Starting and stopping runtimes |
| Platform | Identity provider, model providers, MCP servers, apps' metadata documents, triggers' completion callbacks | 443 | Sign-in, proxying, reading tools, OAuth Connect, callbacks |
| MCP servers that verify identity tokens | Platform (through your ingress) | 443 | Fetching the signing keys at `<APP_URL>/.well-known/mcp-identity-jwks.json` ([MCP identity tokens](/docs/build/mcp-identity)) |
| Your metrics scraper | Platform | 9090 | Prometheus metrics (`METRICS_ADDR`), only if you turn them on. No authentication: allow your scraper only |
| Platform | Tracing collector | 4318 | OpenTelemetry traces, only if you set `OTEL_EXPORTER_OTLP_ENDPOINT`. The chart's public HTTPS egress covers a collector on a public address and port 443; one in the cluster, on a private address or on another port needs a rule of its own (`networkPolicy.egress.tracing`) |
| Agent runtimes | Direct-mode providers and MCP servers | 443 | Only if you use direct mode |
| Everything | DNS | 53 | |

Nothing else should reach the runtimes. In particular, agent pods should accept traffic from the platform alone, so one agent can't call another's runtime or activate a standby runtime of a warm pool.

## The policies need a CNI that enforces them

NetworkPolicy objects do nothing unless the cluster's network plugin (CNI) enforces them: Cilium and Calico do, and so does kindnet in recent kind. A CNI that ignores them, such as flannel on its own, accepts the objects and leaves agents un-isolated without saying so. Check on your cluster that a connection that should be refused is refused: for example, from an agent pod, try the platform's web port, another agent's pod and the internet. The chart's smoke test does exactly this on kind (see [Install on Kubernetes](/docs/operate/kubernetes#check-that-policies-are-enforced)).

On Cilium, the chart's `networkPolicy.flavor: cilium` (and the Kustomize `components/cilium`) allows the platform's access to the Kubernetes API with a `CiliumNetworkPolicy` for the `kube-apiserver` entity. A standard policy can name the API server only by address.

## The policies by hand

If you don't use the chart or the base, write these. In the agents' namespace: deny everything, then allow what runtimes need.

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: agents, namespace: pi-durable-agents }
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - namespaceSelector: { matchLabels: { kubernetes.io/metadata.name: pi-durable-platform } }
          podSelector: { matchLabels: { app: pi-durable-platform } }
      ports: [{ port: 4100 }]
  egress:
    - to:
        - namespaceSelector: { matchLabels: { kubernetes.io/metadata.name: pi-durable-platform } }
          podSelector: { matchLabels: { app: pi-durable-platform } }
      ports: [{ port: 8099 }]
    - to: [{ ipBlock: { cidr: 10.20.30.40/32 } }]   # PostgreSQL
      ports: [{ port: 5432 }]
    - to: [{ namespaceSelector: {}, podSelector: { matchLabels: { k8s-app: kube-dns } } }]
      ports: [{ port: 53, protocol: UDP }, { port: 53, protocol: TCP }]
```

In the platform's namespace, take traffic on 8098 from the ingress only and on 8099 from agent pods only:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: platform, namespace: pi-durable-platform }
spec:
  podSelector: { matchLabels: { app: pi-durable-platform } }
  policyTypes: [Ingress]
  ingress:
    - from: [{ namespaceSelector: { matchLabels: { kubernetes.io/metadata.name: ingress } } }]
      ports: [{ port: 8098 }]
    - from: [{ namespaceSelector: { matchLabels: { kubernetes.io/metadata.name: pi-durable-agents } } }]
      ports: [{ port: 8099 }]
```

If you use direct-mode providers or MCP servers, or apps' MCP servers in direct mode (`AGENTS_CLIENT_MCP_MODE=direct`), allow agents' egress to those hosts too.

## What the platform guards itself

Some addresses are chosen by people other than the operator, so the platform checks them on every connection, whatever your network allows:

- **Teams' own model providers and MCP servers**: `https`, a public address or one inside the **private networks** platform admins list in **Admin › Settings**; never loopback, link-local or cloud metadata addresses. The address is resolved and checked again at every connection and the connection is pinned to it, so DNS can't be changed to point it elsewhere later. Redirects and proxies from the environment aren't used.
- **Apps' Client ID Metadata Documents** (OAuth Connect): public addresses only, no redirects, at most 16 KiB, 5 seconds.
- **Apps' logos** (OAuth Connect, since v0.1.2): the platform fetches an app's published logo itself, from public addresses only, over `https`, without redirects, at most 256 KiB, and serves it from its own address so the console never loads an image from another site.
- **Apps' MCP servers for a thread**: only hosts in `AGENTS_CLIENT_MCP_HOSTS` (none by default).
- **Triggers' completion callbacks** (since v0.4): the same guard as teams' own MCP servers (`https`, public or inside an allowed private network), checked when saved and at every connection, with no redirects, no proxy and a 10 second timeout. The response is never stored or shown.

Platform-level providers and MCP servers that admins add aren't guarded, so admins can point them at internal services. Your NetworkPolicies decide what the platform itself may reach.
