**Admin › Audit log** holds every administrative and membership change on Pi Durable Platform, and every sign-in: who, what, when and how. Each entry is written in the same database transaction as the change, and the log is append-only. Platform admins and auditors read it.

## What's recorded

Every action has a label in the log (since v0.1.1, agents, templates, model providers, models, MCP servers, connected apps and team provider settings too, which v0.1.0 showed as codes such as "Agent: create"). The table gives each **Area** of the filter and its action codes.

| Area | Actions (examples) |
|---|---|
| Sign-in | `auth.login` (Signed in), `auth.logout`, `auth.login_denied` (Sign-in denied: a suspended person) |
| People | `platform.user_role_change`, `platform.user_suspend`, `platform.user_reactivate`, `platform.bootstrap_role` |
| User access (identity provider groups) | `user.group_denied` (Ended access: no longer in an allowed group; by the system, with the reason and how many connected apps were disconnected), `user.group_restored` (Restored access: back in an allowed group; by the person signing in, or by the system when `OIDC_ALLOWED_GROUPS` was removed) |
| Teams | `team.create`, `team.update`, `team.archive`, `team.owner_assign`, `team.member_*`, `team.invite_*`, `team.personal_create`, `team.personal_limits` |
| Keys and service accounts | `api_key.*`, `service_account.*`, `service_account_key.*`, and `*.pepper_rehash` after a pepper rotation |
| Agents | `agent.create` (Deployed agent), `agent.update` (Changed agent), `agent.move` (Moved agent to another team: in both teams' logs), `agent.delete` (Deleted agent), and since v0.4 `agent.runtime_recorded`, `agent.runtime_refused` (Refused an older runtime for the agent), `agent.storage_version_reset` (by an operator's `reset-storage-version`) and `agent.background_abort` (Stopped an agent's background work past the time limit; by the system) |
| Triggers and runs, Trigger limits | Since v0.4: `trigger.create`, `trigger.update`, `trigger.delete`, `trigger.secret_rotate`, `trigger.fire` (Ran trigger now), `trigger.run` (Trigger started a run; by the system), `trigger.run_stop`, `trigger.auto_pause`, `trigger_settings.update`. Never the secrets, payloads or messages |
| Tool approvals | Since v0.4: `tool_approval.request`, `tool_approval.decide` (Approved / Denied a tool call), `tool_approval.timeout`, `tool_approval.cancel`. Never the call's arguments |
| Templates | `agent_template.*`: Created template, Added template version, Asked to publish template, Approved / Rejected template for the catalog, Removed template from the catalog |
| Model providers, Models, MCP servers | `model_provider.*`, `model.*`, `mcp_server.*` (Added, Changed, Deleted …) |
| Platform and users (settings) | `platform.personal_settings` (Changed personal workspace defaults), `platform.model_settings` (Changed team provider and MCP server settings), `platform.secrets_rekey` (Re-sealed stored secrets under the current encryption key: the counts per column, never values; see [Rotating keys](/docs/operate/key-rotation)), and since v0.4 `platform.mcp_identity_key_create` and `platform.mcp_identity_key_rotate` (the MCP identity signing key) |
| Connected apps | `oauth.consent` (Connected app), `oauth.token_issue` (Issued app token), `oauth.revoke` (Revoked app access; reason `user`, `admin`, `client` or `refresh_reuse`), `oauth.client_register` (Registered app), `oauth.trusted_clients_update` (Changed trusted apps), `oauth.client_secret_create` (Issued app secret), `oauth.client_secret_delete` (Deleted app secret: the app and the secret's first characters, never the secret) |
| Conversations | `thread.admin_read` (Read a private conversation, or Read a team conversation): a platform admin read a conversation or one of its documents, with the reason |

Conversations themselves are never in the log.

## Who acted, and how

Each entry has an actor: a **person**, a **service account**, the **system**, or, since v0.4, an **agent** changing the schedules it set itself (shown as **Agent** and its name). For a person it says **how**: signed in to the web app, with an API key (named), or through an app they connected (named). An app's actions are the person's, "via" the app.

## Filters and details

Filter by **Area** (an area, or type to find an exact action by its label), **Target type** (Agent, Template, Model provider, Model, MCP server, App, App connection, Trusted apps, App secret, Service account, Conversation and so on), **Person**, date range, and **Hide sign-ins**. Open an entry for its target, the fields before and after, the metadata (for a conversation read, the **Reason**), the **Request ID** and the client's address. **Export CSV** downloads the filtered log.

The request ID is also in the `X-Request-ID` response header and the platform's logs, so you can follow one request across both.

Team entries also appear in the team's own log, without the client address; see [Team audit log](/docs/teams/audit-log).

## Retention

The platform doesn't delete audit entries. Keep its database in your backups; see [Backups](/docs/operate/backups).
