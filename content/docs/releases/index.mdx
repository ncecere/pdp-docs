These docs describe **Pi Durable Platform v0.3.0**, from 2026-10-20: "Apps at scale".

| Release | Date | Notes |
|---|---|---|
| **v0.3.0** (latest) | 2026-10-20 | [Release notes](/docs/releases/v0-3-0): paging and title search, incremental event streams, steering, safe agent creation, moving agents, OAuth Connect for apps with many people (`prompt=none`, `login_hint`, `agents:read`, app secrets), usage for several agents, and safety fixes. Migrations 18 to 20. |
| v0.2.0 | 2026-10-19 | [Release notes](/docs/releases/v0-2-0): a Helm chart and a Kustomize base, several replicas, metrics and tracing, `rekey`, platform-chosen thread IDs, group re-checks, a harder agents database and safety fixes. Migration 17. |
| v0.1.2 | 2026-10-19 | [Release notes](/docs/releases/v0-1-2): connecting apps' logos show (served by the platform), the agent page's badge follows wake and hibernate. No migrations. |
| v0.1.1 | 2026-10-18 | [Release notes](/docs/releases/v0-1-1): `doctor` checks the agents database, platform staff read any team's agents, the product's logo, console fixes. No migrations. |
| v0.1.0 | 2026-10-18 | [Release notes](/docs/releases/v0-1-0): the first release |

Each release ships two images, for linux/amd64 and linux/arm64, signed with cosign keyless signing:

- `ghcr.io/ncecere/pi-durable-platform`: the platform;
- `ghcr.io/ncecere/pi-durable-platform-runtime`: the agent runtime the platform starts for each agent.

Since v0.2.0, each release also publishes its Helm chart, signed the same way, to `oci://ghcr.io/ncecere/charts/pi-durable-platform`. The chart's version is the release's without the "v" (v0.3.0 is chart 0.3.0).

The project's [releases on GitHub](https://github.com/ncecere/pi-durable-platform/releases) carry the image digests, SBOMs and checksums. The full list of changes is the repository's [CHANGELOG.md](https://github.com/ncecere/pi-durable-platform/blob/v0.3.0/CHANGELOG.md).

Pi Durable Platform follows semantic versioning. Before 1.0, a minor release may include breaking changes; its notes say how to adapt. Upgrading is described in [Upgrades and migrations](/docs/operate/upgrades).

## What's next

The [roadmap](https://github.com/ncecere/pi-durable-platform/blob/main/docs/roadmap.md) is an order of work, not a schedule. Each item is a GitHub issue with the [`roadmap` label](https://github.com/ncecere/pi-durable-platform/issues?q=is%3Aissue+label%3Aroadmap) and a milestone per phase:

Phase v0.2, "Run it anywhere, safely", shipped in [v0.2.0](/docs/releases/v0-2-0), and phase v0.3, "Apps at scale", in [v0.3.0](/docs/releases/v0-3-0). Next:

| Phase | Theme | Items |
|---|---|---|
| v0.4 | Agents that run on their own | The runtime as a library, so teams can build agents with their own documents, hooks and tasks; triggers (schedules and webhooks) that wake agents and start runs; hibernation that knows about background work; a first-party triage agent and deep-research agent; the person behind an MCP tool call, a signed identity for MCP servers (#57); tool approvals |
| v0.5 | Files, memory and limits | Files and images on S3-compatible storage, runtime resources per template version, enforced monthly budgets, limits for shared teams, memory for assistants (an MCP server that remembers for each person), MCP Apps (showing MCP servers' interfaces in the console and in apps), agent runtimes registered by platform admins |
| v0.6 | Coding agents | Workspaces with files and a shell |
| Later | | A Docker Compose deployment without Kubernetes, stronger sandboxing (gVisor or Kata) |
