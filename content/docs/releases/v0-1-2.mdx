Pi Durable Platform v0.1.2, released on 2026-10-19, is a fix release on top of [v0.1.1](/docs/releases/v0-1-1). It fixes two things in the console. It has **no database migrations** (still migration 16) and **no configuration changes**.

## What changed

### Fixed

- **A connecting app's logo shows.** An app that connects with [OAuth Connect](/docs/build/oauth-connect) can publish a logo. The approval screen, **Connected apps** and a person's page in **Admin › Users** showed a broken image, because the console's Content-Security-Policy allows images only from the platform itself. The platform now fetches the logo, checks it and serves it from its own origin. It takes public addresses only, `https` only, no redirects, at most 256 KiB, and PNG, JPEG, GIF or WebP checked by their bytes, never SVG. It caches the logo for an hour. Signed-in people can ask for it at `GET /v1/oauth/client-logo?client_id=…` (rate limited); the request never carries a URL, so it can't be used to fetch other addresses. Without a usable logo the pages show the app's initials. See [Connected apps](/docs/use/connected-apps#the-apps-logo) and [OAuth Connect](/docs/build/oauth-connect#the-logo).
- **The agent page's status badge follows the agent.** After a message woke a hibernated agent from another session or an app, the badge kept saying **Hibernating** until the next poll or a reload. The page now follows the agent's events, so the badge changes when the agent wakes or hibernates.

The full list is in the repository's [CHANGELOG.md](https://github.com/ncecere/pi-durable-platform/blob/v0.1.2/CHANGELOG.md) and its [release notes](https://github.com/ncecere/pi-durable-platform/blob/v0.1.2/docs/releases/v0.1.2.md).

## Upgrading from v0.1.1

Replace both images, the platform and the runtime, by digest, and restart. There are no migrations and no new settings. See [Upgrades and migrations](/docs/operate/upgrades).

## Images

| Image | |
|---|---|
| `ghcr.io/ncecere/pi-durable-platform:v0.1.2` | The platform: distroless, user 65532, read-only root filesystem |
| `ghcr.io/ncecere/pi-durable-platform-runtime:v0.1.2` | The agent runtime: Node.js 22, user 10001, read-only root filesystem with a writable `/tmp` |

Both are tagged `v0.1.2` and `latest`, for linux/amd64 and linux/arm64. Deploy by digest:

```text
ghcr.io/ncecere/pi-durable-platform@sha256:c20916ab720cc5353e17d8ad5d7c12a50fd637b9cbedc1e453f1a99ca6db6deb
ghcr.io/ncecere/pi-durable-platform-runtime@sha256:7b61a2af7b1c4aafec78ec0c5af4e9ae8e6978c1bfd375d9fea9f0b52e32c983
```

The digests are also on the [GitHub release](https://github.com/ncecere/pi-durable-platform/releases/tag/v0.1.2), in its `<image>-v0.1.2.digest.txt` assets.

## Verifying the images

Verify the signatures with [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) **v3.0 or newer** (keyless, GitHub Actions OIDC):

```sh
cosign verify ghcr.io/ncecere/pi-durable-platform@sha256:c20916ab720cc5353e17d8ad5d7c12a50fd637b9cbedc1e453f1a99ca6db6deb \
  --certificate-identity https://github.com/ncecere/pi-durable-platform/.github/workflows/image.yml@refs/tags/v0.1.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
cosign verify ghcr.io/ncecere/pi-durable-platform-runtime@sha256:7b61a2af7b1c4aafec78ec0c5af4e9ae8e6978c1bfd375d9fea9f0b52e32c983 \
  --certificate-identity https://github.com/ncecere/pi-durable-platform/.github/workflows/image.yml@refs/tags/v0.1.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Each image carries its SBOM (SPDX) and build provenance as attestations, and the release has each image's SBOM per platform with `checksums.txt`. `pi-durable-platform version` prints `pi-durable-platform 0.1.2 (<commit>)`; the runtime image is labelled `org.opencontainers.image.version=0.1.2`.
